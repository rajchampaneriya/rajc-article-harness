# Interview notes — issue #3

## The job of the piece (one line)

For developers building or choosing AI-agent tooling: an argued technical essay that stateless runs driven by plain git state beat long-lived sessions that remember everything — cheaper, debuggable, no drift — carried by real examples from building this harness.

## Prompts

Ask the writer first for one unorganised take (three to five minutes, not organized beforehand), then offer these as aids, not a questionnaire:

1. **Trigger.** What happened while building this harness that made you want to write this now — a specific run, bill, bug, or conversation?
2. **One carrying example.** Pick one run where a stateless run on plain git state beat a long-lived session (or lost to one). What broke, what did you do, what changed?
3. **Numbers.** What can you actually cite — cost per run, tokens, minutes lost to drift, crashed sessions — even rough ballparks?
4. **Strongest opposition.** Who disagrees, and what is the best real argument for long-lived memory-heavy sessions? Where does it win?
5. **Unwritten opinion.** What do you say about this in conversation that you have never written down?
6. **Doubt.** Where are you uncertain — what can't plain git state capture — and have you changed your mind about anything here?
7. **Cut.** What would you drop from the conventional version of this piece — which standard take would you cut?

Provenance: model wrote prompts only; no article prose.
